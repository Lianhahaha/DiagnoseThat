# Pulse v1.4.2 — Disk panel fixes

A small update that follows up on [#29](https://github.com/Regncreative/Pulse/issues/29), reported the day after 1.4.1.

## Fixes

- **Total capacity of every drive.** The Disk panel header and overview showed only the system drive, so a PC with two 2 TiB drives showed "2 TiB". They now add up every local drive, for example *Total (2 drives)*. The "disk space is running low" status still looks at the system drive.
- **Drive details are back.** Interface, bus, model, serial number, firmware, partition style, sector size and TRIM showed "—". As with SMART in 1.4.1, PulseService opened the disk with read access, which its LocalService account does not have. These details now come from queries that need no access rights.
- **The system disk, not disk 0.** Those details now describe the disk that holds Windows, found with the documented volume disk-extents query, instead of whichever disk Windows numbered 0. The panel titles them *System disk*.
- **Logs show local characters correctly.** Pulse's logs were already UTF-8, but without a byte order mark Notepad and PowerShell 5 read them as ANSI, so a Polish *Odmowa dostępu* showed as *Odmowa dostÄ™pu*. New log files now start with a UTF-8 byte order mark.

## Upgrade notes

- Confirm **Diagnose → Service** shows **1.4.2** after installing.
- The byte order mark is added to new log files, so today's existing log file stays as it is.
